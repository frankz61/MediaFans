# MediaFans

网盘**搜索 / 转存 / 直链播放**一体化 CLI —— Agent 客户端的第一步（核心工具库）。

把「找片 → 搜资源 → 转存 → 直链 → 播放」整条链路做成一组干净的命令行工具和 Python 库，
后续可以原样包装成 MCP Server 交给任意 AI 客户端调用。

```
mediafans login     →  登录网盘（夸克扫码 / 百度粘贴 cookie+OAuth）
mediafans web       →  本地网页客户端：搜索/转存/浏览/播放一体（推荐，日常用这个）
mediafans discover  →  TMDB 最近热门影视
mediafans search    →  聚合搜索网盘分享链接（PanSou/易搜，多源并发）
mediafans share     →  查看分享里的文件列表
mediafans save      →  转存到自己的网盘（自动建目录、任务轮询）
mediafans ls / find →  浏览/查找自己网盘里的文件
mediafans url / play → 实时生成直链（带 UA/Cookie 校验）/ 调外部播放器
```

## 安装

需要 Python 3.9+：

```bash
python -m venv .venv
.venv/Scripts/pip install -e .        # Windows
# source .venv/bin/activate && pip install -e .   # macOS/Linux
```

## 快速开始

```bash
# 1. 生成配置模板并填写
mediafans config init                 # 写入 ~/.mediafans/config.yaml（或项目目录 config.yaml）
mediafans login                       # 夸克扫码登录（终端显示二维码，APP 扫一下即可）
mediafans login --netdisk baidu       # 百度：粘贴 cookie + OAuth 授权码（两步，见下）
mediafans doctor                      # 体检：配置/账号/搜索源/播放器

# 2. 全链路（推荐在网页里完成）
mediafans web                                    # 搜索 → 勾选转存 → 浏览 → 点播，一站完成

# 命令行同样可用
mediafans discover --type tv -n 10                # 最近热门剧集（TMDB）
mediafans search "流浪地球 4K" --netdisk quark     # 搜资源（--netdisk baidu 搜百度盘）
mediafans share "https://pan.quark.cn/s/xxxx"     # 看看分享里有什么（百度链接自动识别）
mediafans save "https://pan.baidu.com/s/1xxxx?pwd=ab12"    # 转存（提取码带在链接里可省 --code）
mediafans ls /MediaFans                           # 命令行浏览（--netdisk baidu 看百度盘）
mediafans play 沙丘                               # 直链 + 调外部播放器（mpv/VLC…）
```

## 配置说明

`mediafans config init` 生成模板。夸克凭据三种方式（**优先级：中转站 > 扫码登录缓存 > 静态 cookie**）：

| 方式 | 操作 |
|---|---|
| **扫码登录（推荐）** | `mediafans login`：终端渲染二维码，夸克 APP 扫码确认后自动换取并保存 cookie（`quark.cookie`）。网页端右上角「登录」也能扫 |
| **TV 版扫码（实验）** | `mediafans login --tv`：走 TV 版 OAuth，存的是 access_token（`quark_tv.json`）而不是 cookie。**注意**：code 换 token 必须经第三方中转 `api.extscreen.com`（已强制 https），换回来的 refresh_token 等于网盘长期访问权，介意勿用。用 `mediafans tv-check <文件>` 验证 TV 直链是否免凭据 |
| 静态 cookie | 浏览器登录 pan.quark.cn → F12 → Network → 任一请求的完整 Cookie 头，粘贴到 `drive.quark.cookie` |
| token 中转站 | 配置 `drive.quark.token_provider`，每次运行实时拉取（见下） |

百度网盘凭据两套（`mediafans login --netdisk baidu` 一次配齐，网页端「登录」弹窗也能配）：

| 凭据 | 用途 | 获取方式 |
|---|---|---|
| cookie（BDUSS+STOKEN） | 打开分享 / 转存 | 浏览器登录 pan.baidu.com → F12 → Network → Cookie 头整段复制（存 `baidu.cookie`） |
| OAuth refresh_token | 列目录 / 取直链（官方 xpan 接口，稳定通道） | [pan.baidu.com/union](https://pan.baidu.com/union) 免费注册个人应用拿 AppKey/SecretKey 填进 `drive.baidu`，授权一次即可；access_token 30 天自动续（存 `baidu.json`） |

直链特点：SVIP 满速、8 小时有效、必须带 `User-Agent: pan.baidu.com`、支持 Range。
浏览器 `<video>` 发不了自定义 UA，网页播放自动走本地 `/stream` 中继补头，无需配置。

其他配置：

| 项 | 说明 |
|---|---|
| `tmdb.api_key` | [themoviedb.org](https://www.themoviedb.org/settings/api) 免费申请（v3 key 或 v4 Bearer Token 均可），`discover` 命令需要 |

token 中转站对接示例（配置驱动，适配任意 HTTP 接口）：

```yaml
drive:
  quark:
    token_provider:
      url: https://your-relay.example.com/api/quark/cookie
      headers:
        Authorization: "Bearer xxx"
      json_path: data.cookie     # 响应 JSON 里 cookie 的路径；纯文本响应则留空
```

搜索源建议**自部署 PanSou**（公共演示站不稳定）：

```bash
docker run -d --name pansou -p 8080:80 ghcr.io/fish2018/pansou-web
# 然后把 config 里 base_url 改为 http://127.0.0.1:8080
```

## 网页客户端（mediafans web）

一条命令，浏览器自动打开，**搜索 → 转存 → 浏览 → 播放**全部在网页里完成：

- **顶部搜索框：搜的是「作品」，不是「分享链接」**。输入剧名/片名先查 TMDB，
  出海报墙让你确认是哪一部（同名作品很多：搜「沙丘」能同时出 2021 电影、1984 电影、
  2024《沙丘：预言》剧集）。确认之后才有权威的季/集结构，后面找资源、补缺集才有基准。
  点剧集进**剧集矩阵**（见下），点电影直接一键找片转存。
  聚合搜网盘分享的原始入口挪到了「搜资源/转存」页自己的输入框，没有去掉。
- **五个标签页**，按「找片 → 看片」的顺序排：
  **追剧**（海报墙/搜索结果）→ **剧集**（季/集矩阵，见下）→ **最近观看** →
  搜资源 → 我的网盘。网盘目录是排查用的，日常看剧不该从那儿进，所以放最后。
- **搜资源/转存标签页**：点搜索结果（或直接粘贴分享链接）查看分享内容，勾选后一键转存
  （自动建目录、任务轮询），完成后点"打开目录"直接跳到"我的网盘"；需要提取码的在详情页填写后刷新。
  针对网盘分享的实际形态做了几件事：
  - **自动钻过空壳目录**：分享常见「分享 → 片名/ → 4K原盘/ → 真文件」这种层层套娃，
    以前只列顶层，你看到一个空文件夹就卡住了；现在会自动往下钻过「没有文件、只有唯一子目录」的层，
    直接落到有东西的地方，走过的路径记在面包屑里；
  - **能进子目录**：目录点进去看，面包屑随时跳回；想整个目录转存就勾它右边的框；
  - **默认只勾可播放的**：分享里塞的 `【请保存观看】`、`免费享全网资源.docx`、`.nfo`、字幕
    这些默认不勾选、名字置灰，省得一股脑全转存进网盘；
  - **明确告诉你有没有东西**：顶部显示「N 个可播放 · 总大小 / N 个目录 / N 个非媒体」，
    整个目录没有可播放文件时直接说出来；
- **我的网盘标签页**：目录浏览（面包屑导航）+ 最近播放 + 「只看可播放的」开关，
  目录里有几个能播、几个是杂项一眼可见；
- **播放器**：点文件即播，支持拖进度条、多清晰度切换（4K / 超清 / 高清 / 流畅 / 原画，
  切换保留进度，选过的档位会记住）。默认播夸克转码档而不是原画——转码档是 h264+aac，
  浏览器能直接解码，码率也只有原画的几十分之一。另外：
  - **播放列表**：同目录的可播放文件自动成列，上一个/下一个、播完自动连播，追剧不用回列表点；
  - **记住进度**：每个文件的观看位置存在本地，下次点开从上次的位置继续（列表里带进度条）；
  - **自带控制条**：播放/暂停、可拖拽的进度条（带已缓冲区间指示）、时间、音量、
    倍速（0.5×–2×）、全屏。原来页面用的是浏览器原生控制条，但 CSS 里一句
    `::-webkit-media-controls { display:none }` 把它整个隐藏了，等于没有进度条也没有全屏，
    所以改成自己实现一套，样式和页面统一，倍速也不用再翻浏览器的右键菜单；
  - **快捷键**：`空格` 播放/暂停，`←/→` ±10 秒，`↑/↓` 音量，`m` 静音，
    `[` `]` 减速/加速，`f` 全屏，`Esc` 退出网页全屏，`n/p` 下一个/上一个。

  全屏优先用浏览器真全屏；某些环境（嵌入式浏览器、缺少用户手势）会拒绝授权，
  这时自动退化成铺满窗口的「网页全屏」，不会出现点了没反应的情况。

### 手机 / 电视上看（局域网）

默认只监听 `127.0.0.1`，别的设备连不上。要在手机或电视上看：

```bash
mediafans web --lan
```

等价于 `--host 0.0.0.0 --port 8799`。启动后会打印本机地址、局域网地址，
以及一个可以直接用手机扫的终端二维码（令牌已经带在链接里）。

**绑非回环地址时会自动加访问令牌**，因为这个服务能浏览你的整个网盘、能往里转存文件、
还能用你的 cookie 取流，裸奔到局域网等于把网盘交出去。规则：

- 本机（127.0.0.1）访问免令牌，日常用不受影响；
- 外部访问必须带 `?token=`，首页验过一次就种 cookie，之后的 API 和 `/stream` 自动通过；
- 令牌默认随机生成、每次重启都变。想固定下来（比如存成手机书签）用 `--token 你的令牌`。

Windows 上一台机器常有六七个 IPv4（Wi-Fi、VPN 虚拟网卡、WSL、Hyper-V、Docker），
而且 VPN 经常占着默认路由，所以「连一下外网看用哪块网卡」会选错。
这里改成把所有地址列出来按「最像真网卡」排序，首选的那个生成二维码，
其余的也打印出来——首选连不上就换一个试。

### 直链播放（TV token，默认走这条）

登录过 TV 版（`mediafans login --tv`）之后，网页播放器会**让浏览器直连网盘 CDN**，
数据完全不经过本机转发：

```
浏览器 ──/api/play(几KB JSON)──> MediaFans
浏览器 ─────────视频数据────────> 夸克 CDN     ← 本机不在数据链路上
```

原理是两套接口的鉴权模型不同：PC 版直链**必须带 Cookie**（裸请求一律 412），
而 `<video>` 发不出 Cookie，只能本地补头转发；TV 版走 OAuth，
**直链本身免凭据**（实测五档全部裸请求 206），浏览器可以直接播。

有个必须踩过才知道的坑：夸克 CDN 对直链做了**防盗链**，请求带 `Referer` 一律 403。
而 `<video>` 没有元素级的 `referrerpolicy`（试过，无效），只能整页关掉：

```html
<meta name="referrer" content="no-referrer">
```

这一行掉了直链播放就全废，测试里专门盯住了它。

**回退机制**（不用管，自动的）：

- 没有 TV token / token 过期 / 撞上设备数限制 → 整体退回 PC 直链 + 本机转发；
- 单档直链被拒或拿不到数据 → 该档就地换成本机转发继续播，进度不丢；
- 播放器提示会如实写明当前这一路数据到底走没走本机。

想强制全部走转发（排查问题时）：`mediafans web --no-tv`。

实测效果：播放中服务进程停在空载水平（46MB，经代理时是 67MB），
浏览器侧只有一次 `/api/play` 打到本机，视频数据全部来自 `video-play-p-zb.drive.quark.cn`。
这也是**把服务部署到远端小机器唯一划算的形态**——服务器不过流量。

夸克 PC 版直链必须携带 Cookie，而浏览器的 `<video>` 发不出 Cookie，所以页面内置了本地流式转发
（`/stream` 路由自动补凭据、透传 Range），对你完全透明。cookie 始终只在本机使用，即使开了局域网访问也不会发给客户端。
转发做了两层提速，都是实测拍板的：

- **keep-alive 连接池**：`<video>` 每次拖动/续播都会重开 Range 请求，不复用连接就要重新 TLS 握手
  （实测首字节 2.6s → 0.2s），这是卡顿的头号来源；
- **大区间并发分片**：单条 TLS 连接吞吐有上限（实测夸克 6.4 MB/s），而 REMUX 原画需要 8.2 MB/s，
  单连接必然喂不饱。超过 8MB 的区间会拆成 4MB 分片、4 路并发拉取再按序拼回，
  实测 6.4 → 18.9 MB/s。分片小于阈值时（元数据探测、moov 拉取）仍走单连接，避免白白增加延迟。

并发度和分片大小在 `mediafans/proxy.py` 顶部（`PARALLEL` / `PART_SIZE`）。夸克按账号限流，
实测 4 路已接近拐点（6 路 20.0 MB/s、8 路 21.5 MB/s，收益递减），调大意义不大。

外部播放器路径（`mediafans play`）依然可用：

- **mpv / 自定义命令**：能带请求头，直连直链，完全不经过本地转发；
- **VLC / PotPlayer / 系统默认**：带不了 Cookie，自动起本地流式代理再唤起播放器，播放器关闭后代理自动结束。
  这条路同样吃上面的并发分片，用 VLC 直接放 REMUX 原画不再因为带宽不够而卡；
- `--proxy / --no-proxy` 可强制切换代理模式。

**浏览器播放的已知限制**：原画档（MKV 原盘封装、HEVC 视频、DTS-HD/TrueHD 音轨）浏览器解不了。
麻烦的是 Chrome 遇到这种流既不报错也不播，只会一直黑屏往下载——页面为此加了看门狗：
12 秒拿不到画面就停掉后台下载并提示切换档位。想看原画请用 `mediafans play <文件>` 走外部播放器。
好消息是 REMUX 原盘同样有转码档（夸克会转出 4K/超清/高清/流畅），网页里直接选就行。
直链**有时效性**，随取随用，不要缓存。

## 发现：点一下，剩下的不用管

网页端「发现」标签页是海报墙，**剧集和电影各三档**（剧集：今日播出 / 一周在播 /
热门；电影：正在上映 / 即将上映 / 热门），都是华语优先。
**点海报**打开作品页（见下）；**右键海报**是一键找片：
搜网盘 → 逐个打开验证 → 挑最合适的 → 转存 → 打开目录就能播。
命令行是 `mediafans daily` 和 `mediafans auto "片名"`。

### 电影 = 只有一行的「季」

电影和剧集共用同一个作品页、同一份缓存、同一套转存和播放代码——
一部电影就是**只有一行的一季**（`season=0`）。这样进度记录、直链播放、
凭据过期提示、手势播放器全都不用写第二遍，`media_type` 只影响措辞和几个按钮。

真正不一样的只有一件事：**电影没有集号可以归位**。剧集靠集号把文件铺到
E01…E27 上，对不上就丢掉；电影里每个文件都是「整部片」。于是：

- **片名判断成了唯一的闸门**。剧集那边混进别的剧还能靠集号对不上兜住，
  这里兜不住，所以同一套 identity 判断（片名 + 动画/真人）在电影上更吃重。
- **预告片只能靠体积挡**。实测搜索结果里混进来的多是几十 MB 的「预告」「花絮」，
  没有集号可以交叉验证，`MIN_MOVIE_BYTES` 拦一手。
- **同一部片的多个版本不去重**。4K / 1080p / 国语配音 / 导演剪辑版都是合法候选，
  按画质排开让人挑（剧集那边一集只推一个最好的，电影这里列 5 个）。
- **搜索词多一层年份**。同名重拍太常见（《无间道》《木兰》《忠犬八公》），
  但网盘标题经常不写年份，所以带年份和不带年份两种写法都发出去合并。
- **续集号算身份的一部分**。`strip_tech` 把数字当技术标记剥掉了，所以片名判断
  一定认为《流浪地球》和《流浪地球2》是同一部。线上实测搜 2019 版，4 个「版本」
  里混进了 `流浪地球2.2023.2160p.BluRay.Remux…` 和 `Inside the Wandering Earth2`
  （续集的幕后花絮）。分辨办法是只认**紧跟片名、1-2 位、后面不再接数字或 k/p/i**
  的数字——续集号不会有第三位，而年份（2019）、分辨率（2160p）、画质（4K）一定有。

  这一条**只对电影开**（`Work.strict_sequel`）。剧集那边 `末日地堡2 E01.mkv`
  里的 2 常常是季号不是续集号，开了会误杀正片；何况剧集本来就有季号能兜住同名续作。

「网盘里已经有了」时不会再去搜资源——探测很贵，而那时用户要的是「播」。

### 按季/集看：哪一集缺、哪一集能补

整季打包转存必然产生拼盘。实测某个网盘里的末日地堡第二季是这样的：

```
E01-E05  2160p  7.9-9.7GB
E06      1080p  3.26GB      ← 画质掉档
E07      1080p  3.86GB  ┐
E07      2160p  8.95GB  ┘   ← 同一集存了两份
E08        —                ← 缺
E09-E10  1080p  4.54GB
```

点海报打开的是**剧集矩阵**：左边是 TMDB 的权威集列表（季、集号、剧集名、播出日期），
每一集右边显示当前状态：

- **已存**（绿）→ 直接「播放」，用网盘里现成的文件生成直链，不用等转存
- **可补**（黄）→ 列出各个来源「源1 2160p / 源2 1080p…」，点哪个就补哪个
- **缺**（灰）→ 所有来源里都没有这一集

同一集在网盘里存了多份时自动按画质去重（上面 E07 的两份只显示 2160p 那个）。
补集是**按单集转存**，只动这一集，不会把整包重新拉一遍、也不会再造出重复文件。

**只按集号归位是不够的**：同一个目录里混进别的剧很常见。实测那个末日地堡目录里
还躺着 `The.Gentlemen.2024.S01E01~E08`，按集号算的话第一季会被凑成「已存 10 集」，
点播放放出来的是《绅士们》。所以还要看文件名里的片名对不对得上。

但片名过滤本身有风险：发布组常用 TMDB 里没有的别名（`The.Knockout` 之于《狂飙》），
硬过滤会把合法文件静默吃掉，用户看到「缺」就去重复转存，比多显示几个更糟。
所以**先看整个目录里有没有文件对得上片名**——对得上，说明这里的命名习惯带片名，
过滤才可信；一个都对不上，就是别名场景，不过滤。被跳过的文件会在页面上说明数量和例子，
不静默丢弃。（裸文件名如 `S01E01.mp4` 没有片名可比，按所在目录归属算。）

首屏只扫网盘（快），点「找缺失的集」才去搜资源和探测（慢，有进度）。
结果按 (剧, 季) 缓存 30 分钟。

**查询词要多路**：实测同一部剧不同写法命中数差很多——

| 查询词 | 命中 |
|---|---|
| `末日地堡` | 24 条 |
| `Silo` | 11 条 |
| `末日地堡 第二季` | 8 条 |
| `末日地堡 第2季` | **0 条** |

阿拉伯数字的季号基本搜不到，所以查询词用中文数字，而且中文名/原名/带季号/不带季号
几种写法并发跑再合并去重。上面那个缺的 E08，就是靠这个才找到来源补上的
（`末日地堡` 这个词搜到的，带季号的写法反而没有）。

### 一集存多份，播不动就换一份

「哪一份能播」只有播起来才知道，而且失败方式都不报错：

- **原盘 MKV 浏览器解不了**（HEVC 视频 / DTS-HD 音轨）。Chrome 遇到这种流
  既不报错也不播，只会黑屏一直往下载——比报错难查得多。
- **直链被 CDN 拒了**或过期，一点数据都不来。
- **某一版没有中文字幕**，或者是纯外语音轨。

以前每集只留「最好的那一份」（按分辨率和体积猜），碰上这些就得回去重新找资源、
重新转存，一轮下来好几分钟。现在改成：

- **转存**：来源不止一个时给一个「全部 N 版」按钮，一次把多个版本都存下来
  （上限 `DEFAULT_COPY_CAP = 5`，一部热门电影能搜出十几个版本，全存既占网盘
  配额也让切换列表没法用）。转存是秒传，花的是配额不是上传时间。
  单个来源失败不中断——十个里挂两个是常态。
- **播放**：播放器多一排「来源」，随时切。切换**接着当前进度播**，不是从头来。
  `.mkv` 的那几个标成虚线边框，因为它们最可能解不了。
- **失败时**：确定解不了（`undecodable`）就**自动换**到下一个最有指望的副本
  （优先非 mkv），不用让用户先看懂「HEVC/DTS-HD」再自己去点；只是慢
  （`stalled`）则把「来源」栏标黄提示，不掐流。

进度记在**具体文件**上，所以一集的多份各有各的记录。列表和「继续观看」都取
最近更新的那条，换过来源也不会显示成「没看过」，回来时接着播的还是你上次那一份。

### 一键转存整季

扫出来源之后，页脚出现「一键转存 N 集」。27 集逐个点太折磨人。

**不是逐集各挑各的最高画质**——那样会拼出大杂烩，正是用户在末日地堡上遇到的
E01-E05 2160p / E06 掉到 1080p / E07 存了两份。而且 27 集意味着开 27 次分享、
发 27 次转存请求，慢且容易被限流。

所以按「一个来源能覆盖多少集」**贪心分组**：先用覆盖最多的那个来源把能补的都补了，
剩下的再找下一个；覆盖数一样时选画质高的。一份分享的同一层目录只开一次、
只发一次转存请求（夸克单次转存上限 100，内部按 50 分批）。

实测：

```
异人之下 第1季   用 1 个来源补 26 集 → 9.6s，27 集全是同一发布组的 2160p
异人之下 第2季   用 1 个来源补 13 集 → 8.4s
末日地堡 第3季   用 1 个来源补 10 集 → 全 1080p，同一来源
```

几条边界：

- **重复点不会存出 `xxx(1).mkv`**。转存前先列一遍目标目录，同名的算「本来就有」。
  全都存过时按钮直接拒绝，不发请求。
- **一个来源失败不影响其它**。分享随时可能失效，坏链只让它负责的那几集算失败，
  其余照存，最后一并报告「补上 N 集，M 集失败」。
- 没扫出来源时按钮不显示——那时候按了也没用。

### 裸编号文件名：`01.mp4` 到底是不是第 1 集

`parse_episode` 当初写得保守：认 `S01E02`、`1x03`、`第1季第12集`、`EP07`，
但**不认裸数字**，宁可返回 None 也不猜。代价比想象的大——中文网盘里这是最常见的命名：

```
异人之下之决战！碧游村   01x.mkv  02x.mkv  03x.ts … 13x.mkv     ← 整季 13 集
异人之下（2023）全27集    01.mp4   08.mp4   09.mp4 … 27.mp4
```

实测这一季「5 个资源可用，但一集都补不上」——分享是好的、文件数量正好对得上，
只是集号一个都没解析出来。

单看一个 `01.mp4`，那个 1 可能是任何东西，所以不能按单个文件猜。
但**一个目录里躺着十几个只有编号的视频，那就是集号**。所以按批判断：

- 同一层目录里至少 3 个「文件名基本就是个数字」的（数字之外最多 2 个杂字符，
  否则 `4K 高码.mkv`、`2024.IMAX.2160p.mkv` 会被误认）；
- 编号互不重复——撞了说明那些数字是别的意思（画质、分P）。

按目录分别判断：同一份分享可能一层是正片 `01…13`、另一层是花絮 `01…03`，
混在一起判会互相干扰。

### 百度网盘：为什么不走开放平台

百度有官方开放平台（`pan.baidu.com/union`），**注册免费**，看起来是正路。实际走不通，
三道墙都是硬的（文档：使用入门 → 权限与配额，2026-07-03 版）：

> 第三方应用在网盘只能拥有一个文件夹用于存储、上传和下载文件，
> **该文件夹必须位于 /apps 目录下**……对于权限外目录，应用不得
> 查询目录或文件信息；读取、下载或**转存**文件内容。

用户自己的 `/MediaFans` 属于「权限外目录」——列目录、取直链、转存全被明令禁止。
另外未过审应用只有 **10 次/小时**的配额（列一个目录加取一次直链就烧掉好几次），
而规范里又直接点名禁止「利用个人网盘账号……搭建网盘迁移工具」。

所以百度这条线**全程走 cookie**（BDUSS + STOKEN），跟夸克一个路子。
驱动里没有留 OAuth 代码——留着只会让下一个读代码的人再走一遍这条死路。

**扫码登录**（`mediafans login --netdisk baidu`，或网页端「百度·扫码登录」）
用的是 passport 的标准扫码通道，跟网页版扫码同一套。两个坑：

- `channel/unicast` 是**长轮询**，没事件时挂住连接。第一次实测直接 15 秒读超时；
  把超时当失败会让二维码立刻作废。改成 6 秒短超时问一次，超时即「还没动静」。
- **STOKEN 要分两步领**：`qrbdusslogin` 只给 BDUSS，STOKEN 是访问网盘首页时才下发的。
  少这一步转存必挂（errno -4），而且报错很难看懂，所以只拿到 BDUSS 时直接拦下说明原因。

**几个实测出来的接口细节**，都不是看文档能知道的：

| 现象 | 真相 |
|---|---|
| 转存报 errno 200025「提取码输入错误」 | 跟提取码无关。`wxlist` 的 seckey 是 **URL-safe base64**，padding 还用 `~`：`-`→`+`、`_`→`/`、`~`→`=` 三种都要换回来才能当 BDCLND |
| wxlist 说分享好好的，转存报 200025 | wxlist（微信通道）会对**已失效的分享继续返回**完整数据。转存走网页通道，那边 `share/list` 报 -9。一次搜索 14 条：wxlist 放行 4 条，真能转的只有 2 条 |
| 转存「时好时坏」 | 同一个 bug 的表象。只还原 `~` 的话，seckey 里刚好不含 `/` `+` 的分享照样能成，含的就挂——按分享随机复现 |
| 打开分享报 errno -130 | 分享还在、内容没了。`share/verify` 说提取码是对的，但 `share/list` 报 -21（文件已删），`fileNums` 也是 0。当失效跳过就行 |
| `api/list` 对文件路径返回 errno 0 + 空列表 | 跟**空目录**长得一样。只有列表非空才能断定是目录，否则会把文件的 fid 变成路径字符串 |
| 直链下载 403 | 必须带 `User-Agent: pan.baidu.com`。浏览器 UA 403，`netdisk` UA 在 CDN 上报 sign error(31362) |
| 解 302 之后仍然 403 | **解 302 那一跳要带 cookie**，不带的话 Location 里的签名是坏的——而错误出现在后面的 CDN 上 |

**「能浏览」不等于「能转存」**：BDUSS 单独还有效时 `api/list` 一切正常，
但网页登录态可能已经死了。实测这时访问 `pan.baidu.com/disk/home` 会被 302
到登录页，**STOKEN 续不出来**——没有「用 BDUSS 自动续期」这条路，只能重新扫码。
所以批量转存开工前先问一句 `gettemplatevariable`（`check_transfer_ready`），
免得「一键转存 40 集」跑到实际转存那步才报错，前面的扫描全白等。

**「验证通过」得用转存那条通道验**。`open_share` 里加了一次 `share/list`
探针：4 个样本上 `errno 0` ↔ 转存成功、`errno -9` ↔ 200025，完全对应。
它**不需要 bdstoken**，所以登录态过期时照样能用来筛资源——浏览和探测本来
就不该要登录态。wxlist 自带的 `is_zombie` 指望不上，14 条里全是 0，
包括已经死透的那 10 条。

**登录态比 cookie 短命**：实测扫码后二十来分钟到两小时，`gettemplatevariable`
（取 `bdstoken`，转存要用）就开始报 errno -6「用户未登录」，而同一份 cookie 的
`api/list` 一直正常。所以**取直链刻意不带 bdstoken**（实测不需要）——
这样浏览和播放能一直用，只有转存才需要重新扫码。过期时页面会弹一条
可以直接点的「重新扫码登录」提示，而不是甩一个 errno 出来。

### 播放器：悬浮控制条 + 手势

控制条原来是播放区里的流式元素，会占掉一条高度把画面往上挤——全屏时那是一条
**永久黑边**。改成绝对定位贴底 + 从下往上的渐变遮罩，画面占满整个播放区。
进度条和缓冲条的底色也跟着换成半透明白，实色条压在画面上很脏。

- **自动隐藏**：播放中 3 秒无操作隐去，点画面唤出、再点收起。两个边界——
  暂停时不隐（不然会以为卡死），鼠标停在控制条上时不隐（不然想点的按钮会跑掉）。
- **左右滑手势**：左半屏竖滑调亮度、右半屏调音量，中间浮出数值。位移小于 14px
  算点击不算滑动，否则点一下就把音量改了。`#stage` 要 `touch-action:none`，
  不然手机上竖滑会被页面滚动抢走。

**亮度是画面亮度，不是屏幕背光**——浏览器没有调背光的 API，能做的只有对 video 加
`filter: brightness()`。观感接近，但只影响视频区，环境光很强时不如真背光。

### 死链很多，所以分批探、够用就停

搜索源返回的前几条经常是死链。实测搜「异人之下」，前 6 条**全部**是
「好友已取消了分享」；探到第 12 条才有 1 个能打开的。

原来固定只探前 6 条，这类剧就会得到「0 个资源可用」——功能等于没有。
但一上来就探 20 条，正常情况下白等三倍时间（探测是要真去开分享、递归列目录的）。

所以改成**分批探，够用就停**：

- 剧集矩阵：每批 6 个，探完看缺的集是不是都有来源了、**并且至少有 2 个可用来源**，
  才停，最多探到 24 个。「够用」得是「有得选」不是「刚好够」——实测异人之下第二季
  第一个覆盖全季的来源是 286MB/集、画质都读不出来的版本，再探一批才见到 989MB 的。
- 自动找片：每批 6 个，凑够 3 个能打开的就停，同样最多 24 个。

实测两边的表现：

```
异人之下 第1季  正在打开验证 6 个候选… → 前 6 个不够用，再验证 6 个…
                11 个候选打不开（失效/空壳），1 个可用 → 27/27 全部有来源
一人之下 第5季  正在打开验证 6 个候选… → 6 个资源可用      （一批就够，没多探）
```

打不开的数量现在会明说，不然「探了 12 个只出 1 个」看着像出了问题。

### 页面不能被浏览器缓存

页面的 JS 是内联在 HTML 里的，每次部署都变。响应里不带 `Cache-Control` 的话，
浏览器会按启发式缓存一直跑旧代码——表现就是「部署了但线上没生效」，
而且从服务端怎么查都是对的。所以页面和接口一律 `no-store`。

### 同名不同作：动画版、真人版、电影版

《一人之下》是动画（2016，6 季 94 集）；真人版叫《异人之下》（2023 剧版 27 集 /
2024 影版 / 2025 第二季）。TMDB 上是四个独立条目，点进去指向明确，**但网盘不认这个**。

难的地方在于它们连分季名都撞：

| | 动画《一人之下》 | 真人剧《异人之下》 |
|---|---|---|
| 第 4/5 季 | 碧游村篇 / 决战·碧游村篇 | — |
| 第 2 季 | — | 决战！碧游村 |
| 第 6 季 | 唐门篇 | 第 3 季 血战！唐门 |

**改查询词治不了。** 实测搜到的分享里有这么一条：

```
异人之下 第二季 / 异人之下之决战碧游村 (2025) 更新13 完结 1080p/4K 附第一季 动漫全系列
```

一份分享里同时装着真人剧和整套动画，两边的集号完全重叠。所以判断要下沉到
**文件在分享里的路径**（`动漫全系列/一人之下 第一季/E05.mp4`），逻辑在
`agent/identity.py`。两条判据：

- **类型**：动画 / 真人。TMDB 的 genre 16 就是动画，这是最硬的依据；
  路径里的「动漫」「番剧」「剧版」是资源方自己标的，两边对不上才拦。
- **片名**：`异人之下` 和 `一人之下` 只差一个字，但相关度算出来是 1.0 对 0.0，分得开。

**从最里层往外逐段判，第一个说得出话的那段说了算。** 整条路径拼起来判会串味——
分享标题写着「附动漫全系列」，那说的是旁边那个目录，不是根下那个 `E07.mp4`；
整条判会把真人剧的正片当动画拒掉。

两个坑都是在真实数据上撞出来的：

- **中文数字的季号要剥掉**。`第二季/` 这种目录在中文分享里满地都是，
  正则只认 `第\d+季` 的话，`第二季` 会被当成「有片名但对不上」，整季正片全误杀。
- **裸集号不算片名**。文件真的就叫 `01.mp4`、`12x.mkv`、`4K 高码.mkv`——
  中文分享的片名几乎从不在文件名上，而在目录名和分享标题上。
  第一版按「这一段没对上片名」去拒，把 `异人之下（2023）全27集 4K/01.mp4`
  这种正片整份误杀了。

所以最后的规则是**片名只能放行，不能单独拒**；「整份分享是不是另一部作品」
放到分享粒度判（一份分享总有一层会写片名）。代价是命名刻意混淆的分享
（实测有一个叫 `Y .异.R.之.下. 4K[臻彩]`）会被误伤——候选有几十份，丢一份成本很低。

**唯一的例外是本地已存目录**：那里是转存下来的完整发布名，片名信号可靠，
可以据此拒（《绅士们》混进「末日地堡」目录就是靠它拦掉的）。
误伤本地文件会让用户以为缺集去重复转存，代价和丢一份候选完全不同，所以两边规则不同。

实测结果：动画第 5 季 12/12、真人剧第 1 季 27/27，各自都只从对的那部剧取源。

### 华语优先

TMDB 的 `/tv/airing_today` 是**全球榜**，被各国日播肥皂剧刷屏。实测「今日播出」前 8 条：

```
末日地堡(en)  Gran hermano(es)  早春晴朗(zh)  好时光，坏时光(de)
Jornal Nacional(pt)  比勒陀利亚医院(af)  Goede Tijden(nl)  Dark Matter(en)
```

八条里只有一条华语。榜单端点不支持按语言过滤，只有 `/discover/tv` 支持
`with_original_language`，所以华语单独取一档摆在前面，全球榜接在后面——
是「优先」不是「只要」，外语新剧还在，只是不占满第一屏，中间给条「以下为其他语种」。

两个坑：

- **粤语是另一个语言码**。TMDB 把华语拆成 `zh`（国语）和 `cn`（粤语），
  只筛 `zh` 会漏掉整个港片库（2271 部）。用 `zh|cn`。
- **热门榜要有评分门槛**。`sort_by=popularity.desc` 不加门槛的话，
  华语热度榜前三里有两条是没人评分的擦边条目。加 `vote_count.gte=10` 之后是
  明星大侦探 / 仙逆 / 奔跑吧 / 凡人修仙传 / 斗破苍穹，还剩 723 部够铺。
  门槛只加在「热门」上——今日播出和一周在播是新番，本来就没票数，加了会全滤掉。

「今日」按**中国时区**算，不是 UTC 的今天。

**搜索的华语优先要小心。** 中文查询下 TMDB 自己的相关性大多已经排对了
（三体、狂飙、流浪地球都不用动），真正要纠正的是同名撞车：

| 搜 | 原来第一条 | 现在第一条 |
|---|---|---|
| 无间道 | 无间道风云（斯科塞斯翻拍，en） | 无间道（2002，cn） |
| 木兰 | 甜木兰（en） | 花木兰（2009，zh） |
| 长城 | 长城（张艺谋，2016） | **不变** |

最后一行是关键：张艺谋的《长城》在 TMDB 里 `original_language` 是 `en`，
简单按语言排会让《巨兵长城传》顶掉正主。所以排序是
**先按「标题和查询词完全一致」分档，同档之内才华语优先，档内保持 TMDB 原顺序**。
搜「沙丘」全是英语片，顺序一点没动。

分隔条也只在结果确实分成干净两段时才画——搜「长城」第一条就是外语，
这时画一条「以下为其他语种」会跑到最顶上，反而看不懂。

不想要这个行为就在配置里关掉：

```yaml
tmdb:
  api_key: "..."
  prefer_chinese: false     # 默认 true
```

### 看到哪儿了：进度存服务端，不存浏览器

播放进度和「最近观看」记在服务端（`watch.json`，与 `config.yaml` 同目录），
不是浏览器 localStorage。这个服务是手机、平板、电脑一起用的——
在手机上看到 25 分钟，回电脑上要能接着看，进度只记在某一台上等于没记。

一条记录对应一个网盘文件路径。从剧集页播的会带上剧集上下文
（哪部剧、第几季第几集、剧集名、海报），所以「最近观看」能**按剧聚合**：
连看十集也只占一行，显示看到第几集、进度条、以及下一步该干嘛——

```
[海报]  末日地堡
        第2季 第2集 · 命令 　·　 看到 25:11 / 41:24
        ━━━━━━━━━━━━━━━━━━━──────────────
```

看完一集之后这一行会变成「已看完 · 接着看第3集」，点一下直接进剧集页播下一集。
**看完不从列表消失**——正是要靠它接着往下看。

几条边界：

- 开头 30 秒内不算「看过」。点错了、试个画质都会留下记录，下次从那儿续播很莫名。
- 结尾 20 秒内算看完，续播回到 0。片尾曲基本不看，续播到片尾等于没续。
- 时长未知（元数据还没加载完）时不判完成，也不覆盖已知时长。
  否则 `position >= duration - 20` 会把 `0/0` 判成看完，那一集就永久标着 ✓。
- 进度写失败不影响正在看的这一集（`catch` 掉），记不上就记不上。

进度会附在所有列出可播放文件的接口上（剧集矩阵、网盘目录、播放列表），
所以哪儿都能看见细进度线，不用点进去才知道自己看没看过。

**播完自动下一集**：在剧集页看的，下一个是**这一季的下一集**；散片才按目录顺序走。
下一集没存下来就停住——自动跳到第 5 集会让人以为第 4 集没了。

### 「避免空资源」靠的是验证，不是 AI

这点是这个功能的核心，也是设计上最要紧的取舍：**AI 判断不了一个分享链接是不是死的**，
只有真去打开才知道。所以流程是「先探测拿事实，再让模型在事实上做选择」，分三层：

| 层 | 干什么 | 需要 AI 吗 |
|---|---|---|
| **探测**（`agent/probe.py`） | 真去打开每个候选，递归找可播放文件，跳过引流目录 | 不需要 |
| **打分**（`agent/rank.py`） | 用探测到的事实排序：相关性、完整度、画质、片源、体积合理性 | 不需要 |
| **裁决**（`agent/llm.py`） | 在**已验证存活**的候选里做最终选择 | 可选 |

前两层没有 AI 也能完整工作。实测搜「漫长的季节」，5 个候选里探测直接排除 2 个：
一个打得开但**里面一个文件都没有**，另一个只有个 `博搜搜-万能资源搜索引擎.bat`。
标题都写得很漂亮——这就是「空资源」的典型形态，只有打开过才知道。

第三层解决规则搞不定的：同名纪录片 / 前传 / 花絮被当成正片、合集里混装了别的作品、
译名别名对不上、季号写法混乱。实测给它「4K REMUX 的幕后纪录片」和「1080p 的正片」，
它选了正片并说明「候选0是幕后纪录片仅12集，虽4K但不是正剧故排除」——
确定性排序会选错这个（纪录片画质分更高）。

文件名解析（`agent/episode.py`）刻意保守：`S01E02` / `1x03` / `第1季第12集` / `EP07`
都认，但**识别不出就返回 None，绝不猜**。猜错一个集号，整季的完整度判断就全错了。
`Some.Show.2024.1080p.mkv` 里的 2024 不会被当成集号。

### 配置 AI（可选）

```bash
pip install "mediafans[ai]"
```

```yaml
ai:
  enabled: true
  api_key: "sk-..."
  model: claude-opus-5
  base_url: ""        # 指向自建网关时填；留空走官方 API
```

**如果用自建网关要注意**：很多网关只是「长得像 Anthropic」。实测某网关虽然支持
`/v1/messages` 格式，但会**直接丢掉 `system` 参数**（3/3 无视系统提示），
也**不理会 `output_config` 的结构化输出**（返回 markdown 包着的、字段名自创的 JSON）。
所以代码里规则同时写进 `system` 和 `user` 消息，JSON 用容错解析
（去围栏、抓花括号块），两边都能跑。

任何一步出问题——SDK 没装、key 不对、网关超时、返回的 JSON 解析不了、
给的序号越界——都会**退回确定性排序**，链路照常走完。AI 是增强，不是依赖。

### 几个实测踩到的坑

- **完整度的分母**：网盘分享几乎都是单季打包。拿全剧总集数当分母，一个完整单季只算
  25% 完整；拿最长的一季当分母，短的那些季又被误判成残缺。所以没指定季时传的是
  **各季集数的列表**，按资源实际集数去对最接近的那一季。
- **别把参考信息说成硬需求**：一开始把 TMDB 的「首播年份 2019 + 最长季 46 集」
  当条件传给模型，它据此把「2024 年第二季 36 集」判成不匹配，好资源全被拒了。
  现在没指定季时会明确标注「任意一季都可以」。
- **重复点会存出副本**：网盘对同名文件会存成 `xxx(1).mkv`。「点一下就好」的功能
  天然会被重复点，所以转存前先查目标目录，已经有了就跳过。

## 手机上的布局

窄屏（≤820px）走另一套布局，因为原来的左右分栏在手机上是废的：左栏 `min-width:300px`，
375px 的手机上播放区只剩 75px，视频被压成 47×0，文字挤成竖排。

- **竖屏**：视频置顶按 16:9 固定，文件列表在下面占满剩余空间滚动；
  清晰度和播放导航改成横向滚动单行（原本各换两行、共吃掉 176px）；
  路径输入框隐藏（手机靠点文件夹和面包屑导航）；音量交给手机物理键。
- **还没开始播时整个播放区不占位置**，列表能拿到全屏（实测 723px、7 行全可见）。
- **在「搜资源/转存」页时视频压到 24vh**、隐藏播放器附属信息，
  否则分享文件列表会被挤成 0 高度，根本没法勾选文件。
- **横屏手机**（宽够但高 ≤520px）反而改回左右分栏 —— 堆叠会把列表顶到屏幕外 162px。

`100dvh` 而不是 `100vh`，避免手机地址栏收放时被截掉一截；触摸目标放大到 44px 上下。

## 资源占用与小内存部署

实测（Windows，播 1080p 转码档，`常驻 / 独占` 两个口径）：

| 场景 | 默认配置 | 省内存配置 |
|---|---|---|
| 空载 | 38.4 / 25.3 MB | 38.4 / 25.1 MB |
| 1 路播放峰值 | 67.3 / 52.8 MB | 52.1 / 35.8 MB |
| 3 路并发播放峰值 | **105.8 / 90.7 MB** | **58.6 / 43.7 MB** |

峰值几乎全来自并发分片缓冲：`PART_SIZE × PARALLEL × 同时在播的路数`，默认每路 16MB。
128MB 以下的小机器用环境变量调小：

```bash
MEDIAFANS_PART_SIZE=1048576 \
MEDIAFANS_PARALLEL=2 \
MEDIAFANS_READAHEAD_CHUNKS=8 \
  mediafans web --lan
```

代价说清楚：并发度降到 2 之后单流吞吐约 7.8 MB/s（实测），**喂不饱 8.2 MB/s 的 REMUX 原画**，
但转码档只要 0.4–3.5 MB/s，完全够。小机器上本来也不该播原画。

**放到远端服务器之前想清楚数据走向**：夸克 CDN 在国内，把转发放到境外服务器意味着
「国内 CDN → 境外机器 → 你」，绕一圈，带宽还得服务器出——一部 4K 转码档 4.4GB，
小机器的流量配额撑不了几部。

- **只部署 PanSou（搜索 API）到小机器**：合适。搜索是小流量、延迟不敏感的活。
  但注意 PanSou 的 `CACHE_MAX_SIZE` 默认 100MB，小机器上要压到 `-e CACHE_MAX_SIZE=20`，
  再配 `-e GC_PERCENT=30`。
- **完整 MediaFans 放远端**：只有在「浏览器直连网盘 CDN、服务器不过流量」的前提下才划算，
  也就是 TV 版 token 那条路（见上文，已验证直链免凭据，但还没接进网页播放器）。
  否则建议就在本机或家里的设备上跑。

## 让搜索源更丰富

**先搞清楚瓶颈在哪**：PanSou 服务端本身就是聚合器，一个实例背后是几十个 TG 频道 + 几十个
插件（实测公共实例报 60 频道 / 43 插件，单次搜索能命中 8 种网盘）。所以问题基本不是
「站点太少」，而是这三条：

| 问题 | 实测表现 | 对策 |
|---|---|---|
| 公共实例不稳 | 同一关键词三次返回 **13 / 74 / 0** 条 | 自部署，或配多个实例故障转移 |
| 拿回一堆用不了的结果 | 36 条里只有 19 条是夸克（其余转存不了） | 用 `cloud_types` 让服务端过滤 |
| 只配了一个源 | 它一挂就全挂 | `fallback_urls` |

按性价比排序：

**1. 自部署 PanSou（最有效）**

```bash
docker run -d --name pansou -p 8888:8888 \
  -e CHANNELS="tgsearchers3,yunpanx,yunpanpan,yunpanall,tianyifc,shareAliyun" \
  -e ENABLED_PLUGINS="pansearch,hunhepan,qupansou,panwiki,panta,jikepan" \
  ghcr.io/fish2018/pansou
```

`CHANNELS` 和 `ENABLED_PLUGINS` 就是「源」本身，想多丰富就填多少。注意 `ENABLED_PLUGINS`
不填的话插件是不启用的。部署完把 `base_url` 换成 `http://127.0.0.1:8888`。

**部署到远端小机器时**（实测 1C/950MB 的 VPS 上稳定占用约 20MB）：

- 加 `-e CACHE_MAX_SIZE=20 -e GC_PERCENT=30` 压缓存，`-m 128m` 给个内存上限兜底；
- 新版镜像默认 `AUTH_ENABLED=true`，走的是 JWT（24 小时过期），MediaFans 没接。
  与其半吊子集成，不如**关掉它自带鉴权、改在网络层挡**：容器只绑 `127.0.0.1`，
  外面用 nginx 开一个带**秘密路径前缀**的 HTTPS 入口，其余路径 `return 444`：

```nginx
limit_req_zone $binary_remote_addr zone=pansou_rl:1m rate=30r/m;
server {
    listen 12582 ssl;
    server_name your.domain;
    ssl_certificate     /etc/letsencrypt/live/your.domain/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your.domain/privkey.pem;
    location / { return 444; }                 # 扫端口什么也拿不到
    location /<随机前缀>/ {
        limit_req zone=pansou_rl burst=10 nodelay;
        proxy_pass http://127.0.0.1:8890/;
        proxy_read_timeout 90s;
    }
}
```

然后 `base_url: https://your.domain:12582/<随机前缀>` —— 客户端零改动，因为秘密就在路径里。
实测自建 vs 公共实例（三个关键词）：**26 / 26 / 27 条且零失败**，公共实例是 13 / 21 / 0 和 0 / 1 / 0。

**2. 配多个实例做故障转移**（已内置）

```yaml
sources:
  - type: pansou
    base_url: https://so.252035.xyz
    fallback_urls:
      - https://pansou.app
```

前一个报错**或者返回 0 条**都会自动换下一个 —— 公共实例返回 0 往往是它自己限流，不是真没资源。
实测加了备用实例后，三次搜索从 `0 / 13 / 0` 变成 `20 / 11 / 4`，不再出现空结果。

**3. 把服务端的开关用起来**

搜索时选了网盘，就会自动带上 `cloud_types` 让服务端过滤，同一次请求里能用的结果多得多。
还可以在 source 里固定这些参数：

| 参数 | 说明 |
|---|---|
| `cloud_types` | 只要指定网盘（`quark,aliyun,115,baidu,xunlei,tianyi,uc,123,magnet` …） |
| `src` | `all` / `tg` / `plugin`，实测 `tg` 的夸克命中率明显高于 `plugin` |
| `channels` | 指定 TG 频道，留空用服务端默认 |
| `plugins` | 指定插件 |
| `refresh` | `true` 跳过服务端缓存，慢一倍但更新 |
| `conc` | 并发度 |

**关于其他聚合项目**：PanHub、CloudSaver 之类和 PanSou 是同类东西，源池高度重叠，
再接一个的边际收益远不如把一个实例配好。真要加，`SearchProvider` 子类 + 注册一行就行
（见 `mediafans/search/`）。另外 **yiso.work 的接口已经失效**（返回 HTML 不是 JSON），
配置里那条一直是注释状态，不用管它。

## 项目结构

```
mediafans/
├── cli.py              # 命令行入口（typer）
├── config.py           # 配置加载（yaml，含模板）
├── auth.py             # 夸克扫码登录（uop.quark.cn CAS：取码/轮询/换票）
├── tokens.py           # token 中转站客户端
├── metadata/tmdb.py    # TMDB 热门/搜索
├── search/             # 搜索聚合：pansou / yiso（多源并发、去重、单源失败不阻断）
├── drive/              # 网盘驱动：base.py 抽象 + quark.py 实现
│                        #   分享stoken/文件列表/转存/任务轮询/目录管理/直链(含Set-Cookie)
├── player.py           # 播放器探测与命令构建（mpv/PotPlayer/VLC/自定义）
├── proxy.py            # 本地流式转发（Cookie 注入 + Range 透传）
├── web.py              # 本地网页播放器（目录浏览 + video 点播，内置转发）
├── models.py           # MediaItem / ShareLink / DriveFile / PlayTarget
└── utils.py            # 链接解析/网盘分类/路径规范化等
tests/                  # 45 个离线测试（MockTransport 模拟夸克接口，不打真实网络）
```

新增网盘（阿里/百度/115…）：实现 `drive/base.py` 的 `BaseDrive` 接口并在 `drive/__init__.py` 注册即可，CLI 层不用动。

## 已知坑

- **账号风控**：转存/直链请求别高频并发（本项目单线程串行，天然安全）；
- 演示搜索站限流/超时常见，报错会列出失败源，不影响其他源；
- 夸克部分资源（会员/风险文件）拿不到直链，会透传平台错误信息；
- 影视资源分享属版权灰色地带，**仅限个人学习自用**。
